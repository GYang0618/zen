# ADR-003：文件与对象存储归内核

- **状态**：已采纳  
- **日期**：2026-08-24  
- **决策者**：平台架构（Zen）  
- **相关**：[平台总览](../architecture/platform-overview.md) · [功能清单 FILE-*](../product/feature-catalog.md) · [ADR-002](./002-tenant-readiness.md)

## 背景

一期将 FILE-01/02/03 放在 `plugins/files`。实际上传已被头像、后续附件、导出产物等内核/业务共用。插件可停用、禁止跨插件深引用，且当前实现存在同租户越权下载、客户端可写 `storageKey`、头像依赖插件权限等问题。

对象存储若做成可停用插件，平台无法安全托管任意需要附件的能力。

## 决策

**统一文件上传、对象存储、元数据、授权与审计进入 API 内核；`plugins/files` 移除；管理页上收为系统模块。**

具体约束：

1. 传输默认 **预签名直传**（浏览器 PUT 到对象存储，API 只签发与确认）。  
2. 对象存储统一使用 **Docker 私有化 MinIO**（S3 兼容）；不保留本地磁盘双轨。  
3. 业务与前端只持有 `fileId`，不暴露 bucket / `storageKey` / 永久 URL。  
4. 权限码使用内核命名空间：`system:file:*`、`system:storage:*`。  
5. 头像等自助场景走「已登录 + purpose 策略」，不要求文件管理权限。  
6. **多租户暂不实现**：请求固定 `DEFAULT_TENANT_ID`；`tenantId`、对象键 `tenants/{tenantId}/...`、策略/配额接口按租户预留。  
7. 管理 UI 位于 `apps/web/src/features/system/files`，随内核权限控制，不随插件启停。

## 理由

| 因素 | 说明 |
|------|------|
| 判定原则 | 拆掉上传后平台无法安全托管头像与未来附件，属内核 |
| 安全 | 下载必须叠加 RBAC + tenantId + DataScope + 所有权/绑定 |
| 运维 | MinIO 与 Postgres 一样是基础设施，不是业务插件 |
| 演进 | S3 适配器可在不改业务的前提下替换公有云，但本期不接入 |

## 后果

### 正面

- 头像与系统模块不再倒挂插件  
- 停用任意业务插件不影响存储  
- 预签名直传避免 API 中转大文件  

### 负面 / 风险

- 设计基线从「文件=插件」改为「文件=内核」，需同步功能清单与总览  
- 本地开发必须启动 MinIO  
- 历史 `stored_files` 与本地 `uploads/` 需要一次性迁移  

### 不做什么（本期）

- 公有云 OSS/COS 适配器（接口预留）  
- 完整网盘：分享外链、版本树、全文检索  
- 真正多租户运营与跨租户去重  

## 备选方案（未采纳）

| 方案 | 未采纳原因 |
|------|------------|
| 保留 files 插件 + 其它插件 dependsOn | 内核头像仍倒挂；停用语义脏 |
| 仅 API 模块化、管理页仍在插件 | 启停与菜单过滤仍把存储当成可选能力 |
| 本地磁盘 + MinIO 双驱动 | 双轨测试与路径规范分裂 |
